# GemAtlas 欧泊首页 Hero 设计规范

## 状态

- 状态：实现完成，等待用户体验复核。
- 日期：2026-09-07
- 范围：独立首页 Hero 与进入知识百科主页的入口体验。
- 技术约束：GemAtlas 当前使用 VitePress、Vue 3 与 TypeScript，不迁移到 React、Tailwind 或 shadcn。

## 目标

把首页第一屏做成“从一束光，认识一颗宝石”的沉浸式入口：访客先看到暗场中的欧泊成品，再看到全屏光线缓慢扫过，欧泊变彩逐渐显现，最后通过顶部模块入口进入五个知识板块。欧泊的成因、变彩原理、切割和鉴定细节仍由现有知识页面承载。

## 已确认方向

采用 A 方向的叙事骨架：展柜正面、欧泊成品微距、主体占据主要视觉重量。候选素材为 Wikimedia Commons 的 Rainbow Shield 欧泊吊坠照片（2807×3358，作者 Dpulitzer，CC BY-SA 4.0）。正式使用时必须保留本地副本，并在 `docs/image-credits.md` 记录作者、来源、许可和处理方式。

- 保留欧泊、金属镶嵌和真实反光，不用生成式宝石替换主体。
- 通过微距裁切和轻微镜头推进让成品进入画面主体，不再固定在页面下方。
- 标题始终位于视觉中心，利用主体偏移和暗部留白保证可读性。
- 顶部使用玻璃胶囊模块键：`01 分类`、`02 鉴定`、`03 切割`、`04 分级`、`05 画廊`。
- 移动端允许模块胶囊横向滚动，每个入口触控区域不小于 44×44px。

## 动效时间线

动效目的是解释和避免突兀切换，不是持续刺激。总循环约 20 秒：

| 时间 | 状态 | 行为 |
| --- | --- | --- |
| 0–3 秒 | 暗场建立 | 成品低亮度显示轮廓，标题保持可读。 |
| 3–15 秒 | 光线揭示 | 光线以匀速、低对比度从全屏暗部扫过；经过欧泊时，变彩从局部逐步扩展。使用 `linear`，不在中段加速。 |
| 15–20 秒 | 色彩停留 | 保留完整变彩与金属反光约 5 秒后循环。 |

首版使用 CSS animation、`transform`、`opacity` 和 `clip-path`，配合本地真实照片实现镜头推进、光线扫掠和色彩显现，不引入动画库。若之后取得合适的真实欧泊视频，只替换媒体层，不改变标题、导航和无障碍接口。

必须满足：

- 光束覆盖全屏，不固定为左侧单根竖线。
- 光束恒速移动，亮度和颜色缓慢变化，不制造突然闪烁。
- `prefers-reduced-motion: reduce` 时停留在清晰静态画面。
- hover 动效只在支持精确指针的设备启用，键盘焦点必须立即可见。

## 页面与导航

根首页展示欧泊 Hero；主行动入口进入现有中文知识百科主页 `/zh/`，英文入口进入 `/`。顶部五个模块键复用现有模块路由，不复制模块内容。旧首页内容保留为知识主页。

建议组件职责：

- `GemAtlasLanding.vue`：Hero 结构、文案、入口和 reduced-motion 状态。
- `OpalRevealMedia.vue`：素材加载、fallback、光束和变彩揭示层。
- `ModuleJumpNav.vue`：五个模块入口、键盘焦点和移动端滚动。

## 加载与无障碍

- 正式素材本地化，首页不依赖第三方 CDN。
- 固定媒体容器比例，避免图片加载造成布局位移。
- 图片失败时显示深色展柜背景、标题和知识主页入口。
- 若未来使用视频，提供本地 poster、`muted`、`playsInline` 和移动端静态降级。
- 图片拥有准确 alt，光束和色彩层标记为装饰性内容；普通文本对比度至少 4.5:1。
- 五个模块入口是真实链接，拥有清晰焦点环，不只依赖颜色区分。

## 验收标准

- 第一眼主体是欧泊成品，标题位于屏幕中央且保持可读。
- 光线约 15 秒匀速扫过全屏，变彩缓慢显现并停留约 5 秒。
- 顶部入口编号完整连续为 01–05，桌面端和窄屏均可用。
- `pnpm validate:data`、`pnpm generate:pages`、`pnpm test`、`pnpm build` 通过。
- 完成真实浏览器检查：首屏、模块跳转、主入口、键盘焦点、图片失败和 reduced-motion。
