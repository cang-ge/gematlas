# GemAtlas README 扩写设计

日期：2026-08-31

## 目标

将 GemAtlas 的三份 README 从简短项目索引扩展为兼顾用户理解与技术验证的项目介绍文档，服务于开源访客、潜在贡献者和求职面试官。

## 范围

只修改以下文件：

- `README.md`
- `README.en.md`
- `README.zh.md`

保留并引用现有架构卡片：

- `docs/architecture/gematlas-architecture.png`

不修改业务代码，不修改知识库正文，不带入工作区中与本任务无关的未提交文件。

## 信息架构

三份 README 使用对应章节结构：

1. 项目标题与一句话定位
2. 项目亮点与核心指标
3. 在线体验与快速开始
4. 项目解决的问题
5. 用户可以获得什么
6. 五大内容模块
7. 系统架构与数据流
8. 数据模型与内容生产方式
9. 自动化构建和质量门禁
10. 仓库目录结构
11. 本地开发、构建、测试、部署
12. 内容来源与免责声明
13. 贡献指南与许可证

`README.md` 作为英文主入口，`README.en.md` 提供英文详细版，`README.zh.md` 提供中文详细版。三份文档的事实口径、命令、链接和章节含义保持一致。

## 内容原则

- YAML 是内容唯一事实来源，Markdown 页面由构建脚本生成。
- 以当前仓库事实为准：60 个宝石条目、5 个内容模块、7 个晶系、18 件顶级珠宝作品和 70 项自动化测试。
- 明确区分已实现能力与后续规划，不将计划内容写成现状。
- 用“内容工程系统”解释项目价值，说明数据建模、校验、页面生成、双语同步和部署之间的关系。
- 保留 GIA、SSEF、Gübelin 等现有内容来源与署名说明。
- 避免“行业首创”“权威”“完美”等无法从仓库验证的夸张表述。

## 技术重点

README 将重点解释以下可验证能力：

- VitePress + Vue 3 + TypeScript 静态站点
- YAML 数据源与 Zod Schema 校验
- TypeScript 页面生成器和专题页生成器
- 英文与中文目录结构同步检查
- Vitest 数据完整性与国际化一致性测试
- GitHub Actions 构建和 GitHub Pages 发布
- 本地搜索与深色宝石学博物馆风格主题

## 架构展示

架构卡片放在系统架构章节的前部，随后补充文本化的数据流和目录说明。图文顺序为：

内容维护者 → YAML 数据源 → Schema 校验 → 页面生成器 → VitePress 站点 → GitHub Pages

数据校验和双语同步检查作为构建门禁，只有通过检查后才进入部署流程。

## 验收标准

- 三份 README 的章节结构和事实口径一致。
- 架构卡片使用相对路径，GitHub 页面可以正常显示。
- README 中的命令与 `package.json` 脚本一致。
- `pnpm validate:data` 通过。
- `pnpm sync:content` 通过。
- `pnpm test` 通过。
- `pnpm build` 通过。
- `git diff --check` 通过。
- 最终提交只包含本次 README 扩写和必要的设计文档。
